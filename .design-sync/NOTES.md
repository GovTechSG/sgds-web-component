# design-sync notes — @govtechsg/sgds-web-component

SGDS is a **lit-html web-components** library with **React wrappers** (`lib/react/`).
The sync ships the React wrappers as the components a React design agent renders;
the wrappers register the `<sgds-*>` custom elements on import, so lit-html story
previews render too.

## Environment / build sequence (re-sync must replicate)
- Node **22.18.0** via `fnm exec --using=22.18.0 -- <cmd>` (repo `.nvmrc`; corepack → pnpm 10.26.2).
- Install: `pnpm install --frozen-lockfile`.
- pnpm does NOT hoist `react-dom`/`scheduler`/`react-is`/`@types/react` to top-level
  `node_modules`. `[GENERAL]` The converter's `vendorReact` + dts step need them there.
  Recreate top-level symlinks after every install (gitignored, so not durable):
  - `node_modules/react-dom` → `.pnpm/react-dom@*/node_modules/react-dom`
  - `node_modules/scheduler` → `.pnpm/scheduler@*/node_modules/scheduler`
  - `node_modules/react-is` → `.pnpm/react-is@*/node_modules/react-is`
  - `node_modules/@types/react` → `.pnpm/@types+react@*/node_modules/@types/react`
- `buildCmd` = `pnpm build && pnpm run utility:storybook && pnpm run write:stories && node .design-sync/build-css.mjs`
  (`write:stories` generates `stories/components/*.stories.js` from templates; without it
  the storybook glob is empty. `build-css.mjs` regenerates the foundation stylesheet.)
- Rebuild `.design-sync/sb-reference` whenever DS source or stories change:
  `npx storybook build -c .storybook -o "$(git rev-parse --show-toplevel)/.design-sync/sb-reference"`.
- Fresh-clone extras: recreate `.design-sync/node_modules` → `.ds-sync/node_modules`
  symlink (the previews.mjs fork imports bare `esbuild`).
- Converter run:
  `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./.design-sync/react-entry/index.js --out ./ds-bundle`

## Config decisions (`.design-sync/config.json`)
- `entry` → `.design-sync/react-entry/index.js` — a committed shim that
  `export * from "../../lib/react/index.js"`. WHY: the package's declared typings
  (`lib/index.d.ts`) only side-effect-register custom elements and export NOTHING, so
  discovery found 0 components. The React wrapper index exports 73 PascalCase symbols.
  The shim's own `package.json` (mirrors the real name/version/deps) makes it `PKG_DIR`,
  so `findTypesRoot` reads `react-entry/index.d.ts` → the 73 React exports.
  `[GENERAL]` Because the shim is PKG_DIR, `cfg.cssEntry` is resolved relative to and
  bounded within `react-entry/`, so `styles-foundation.css` is emitted THERE by build-css.mjs.
- Do NOT re-export `../../lib/index.js` from the shim: it registers the same custom
  elements a second time and the components call `customElements.define()` unguarded →
  "already used with this registry". The React wrappers alone register everything.
- `globalName` → `SGDS` (window.SGDS.SgdsButton, …).
- `titleMap` maps each storybook title segment `X` → export `SgdsX` (stories are titled
  `Components/Button`, exports are `SgdsButton`).
- `cssEntry` → `styles-foundation.css` (in react-entry/, generated by build-css.mjs from
  `.design-sync/styles-src.css`). SGDS component styles live in shadow DOM (in the JS
  bundle), so `_ds_bundle.css` is tokens + base + utilities + story layout helpers only:
  `lib/themes/day.css` (+root+responsive) + `night.css` + `lib/css/sgds.css` (reboot/grid)
  + `.storybook/utility.css` (sgds: utilities) + `.storybook/global.css` (d-flex helpers).
- `overrides.*.cardMode: "column"` on 14 components whose stories are wider than a grid
  cell (Badge, Breadcrumb, Button, Card, Checkbox, CloseButton, IconCard, ImageCard,
  Mainnav, Pagination, Sidebar, Skeleton, Table, ThumbnailCard).

## Lib forks (`.design-sync/overrides/`, declared in cfg.libOverrides)
- `preview-gen-storybook.mjs` — `[GENERAL]` stories return lit `TemplateResult`, which the
  React preview mount (emit.mjs, unforkable) can't render. The fork wraps every composed
  story in a `__bridge` React component that renders the lit output via lit's own
  `render()` into a host div. `lit` bundles into the same preview compile, so the story's
  `html` and the bridge's `render` share one lit instance.
- `previews.mjs` — `[GENERAL]` pins esbuild `target: es2020` +
  `tsconfigRaw.experimentalDecorators` + parses story `.js` as `ts`. WHY: the stock
  preview build sets no target → esbuild defaults to `esnext` and PRESERVES decorator
  syntax (mock elements in some stories use `@customElement`/`@property`) → browser
  "Invalid or unexpected token" / "Unsupported decorator location: field". es2020 +
  experimentalDecorators (lit's decorator mode, needs useDefineForClassFields:false)
  downlevels both class and field decorators.

## Known / accepted
- Inter font ships via a remote `@import url(fonts.googleapis.com…)` in styles.css
  (scraped from storybook, the converter's intended mechanism for remote stylesheets).
  The reference storybook uses the same remote, so grading is apples-to-apples.
- `RENDER_THIN` on SgdsMasthead, SgdsProgressBar, SgdsPagination — legitimately thin/
  low-paint components (thin bars, page numbers); they render correctly.
- Subcomponents (SgdsAccordionItem, SgdsTableRow, …; 73 exports vs 47 carded components)
  have no storybook title of their own, so they're not carded but ARE in the bundle and
  usable by the design agent.

## Owned previews (`.design-sync/previews/`) and why (fan-out learnings)
- `SgdsTextarea.tsx` — the `override-invalid-feedback` story shares the display name
  "Validation" with another story, so both deduped to one export and one was `unpaired`.
  The owned preview adds a distinctly-named 5th export so compare's order-fallback pairs it.
- `SgdsFileUpload.tsx` — `[GENERAL]` stories whose visible state is set by an inline
  `<script>` (not props/lit template) render blank: lit's `render()` inserts the script
  into the host div but a template-cloned script never executes. Fix = own the `.tsx` and
  reproduce the script's imperative work in a post-render effect against the upgraded
  custom element (`__bridgeWithFileState` seeds a File → dispatches change →
  `setFileUploadState`). Also affects FileUpload's uncaptured Error/Success tail stories.
- `SgdsMainnav.tsx` — `[GENERAL]` stories slotting a root-absolute storybook-static asset
  (`<img src="/logo.png">` from `.storybook/static/`) render broken images: the preview
  host doesn't serve that dir. Fix = inline the asset as a base64 data URI in the owned .tsx.
- `[GENERAL]` `<dev-console-widget>` (GovTech dev-console-gateway, a REMOTE script loaded via
  `.storybook/preview-head.html`) appears in nav/masthead stories. It is preview-chrome, NOT
  an SGDS component, and never renders in the sync preview — treat its absence as an
  acceptable `close` delta; do not try to reproduce it. (SgdsMainnav graded `close` for this.)

## Overlay / cardMode notes
- `SgdsToast` → `cardMode: "single"`: its Basic story wraps the toast in a
  `position:fixed` `<sgds-toast-container>` that paints outside a grid cell; single
  mode contains it. Storybook's reference capture of Basic is blank (the fixed toast
  paints off the captured canvas) — Basic was graded `match` on the preview render
  (gated-reference rule).
- `SgdsModal` → `skip` the 5 size stories (interaction-driven; sb-error in storybook too).
- Other overlays (Drawer, Tooltip, Dropdown, OverflowMenu, Datepicker, Sidebar) render
  their triggers CLOSED in captured stories — no bleed, no cardMode:single needed.

## Re-sync risks (watch these)
- STORY_CAP tail (uncaptured stories, verified-by-upload — NOT individually graded):
  raising `--max-stories` would surface these and some need work — notably Toast's
  position/stacking tail (fixed toast-container → blank in storybook; some slot
  `/logo.png`) and FileUpload's Error/Success tail (inline-`<script>` state → extend
  the owned `.tsx`'s `__bridgeWithFileState` with 'error'/'success'). Keep the cap as-is
  unless those tail variants must be verified.
- The pnpm hoist symlinks + `.design-sync/node_modules` symlink are gitignored and vanish
  on a fresh clone / reinstall — recreate them (see build sequence).
- `cardMode: column` list is static — a newly-added wide component would need adding.
- If a new story defines a mock element with a decorator style es2020 can't handle,
  revisit the previews.mjs fork target.
