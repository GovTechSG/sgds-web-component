# Native Validation

SGDS form web components have HTML [constraint validation](https://developer.mozilla.org/en-US/docs/Web/HTML/Constraint_validation) and SGDS's own validation behaviour built in via the [ElementInternals API](https://developer.mozilla.org/en-US/docs/Web/API/ElementInternals).

## How validation works

SGDS validation combines native HTML constraint validation with additional UX behaviour. The `hasFeedback` prop controls whether visual feedback (error styling and/or error text) is shown to the user.

### Validation lifecycle

1. **On blur (after touch)** — When a user focuses a field, interacts with it, then moves away, the field is validated against its constraints (`required`, `pattern`, `min`, `max`, `minlength`, `maxlength`). If invalid, the error state and message are shown.

2. **On input (while typing)** — While the user is typing, the invalid state is temporarily cleared to give them a chance to correct their input. Validation re-fires on the next blur.

3. **On submit** — A final validation check runs on all fields when the submit button is clicked. If any field is invalid, the form submission is blocked.

4. **On reset** — Clicking the reset button clears all validation states and restores fields to their default values.

5. **When disabled** — Disabled fields are excluded from validation entirely.

### The `hasFeedback` prop

All form components accept a `hasFeedback` prop that controls what feedback the user sees:

| Value | Behaviour |
|---|---|
| `"both"` | Shows both the invalid style (red border) and the error message text |
| `"style"` | Shows only the invalid style (red border), no error text |
| `"text"` | Shows only the error message text, no style change |
| *(not set)* | No visual feedback — validation still runs internally and blocks submission |

### Constraint validation attributes

These native HTML validation attributes are supported across components:

| Attribute | Purpose | Components |
|---|---|---|
| `required` | Field must have a value | All form components |
| `pattern` | Value must match a regex | Input |
| `min` / `max` | Numeric or date range | Input, QuantityToggle, Datepicker |
| `minlength` / `maxlength` | Text length range | Input, Textarea |

> **Try it:** Use the sample form below to observe the validation lifecycle. Focus and blur on empty required fields to see onChange validation. Type into fields to see the invalid state clear during input. Click Submit on an empty form to see all fields validated at once. Click Reset to clear all states.
